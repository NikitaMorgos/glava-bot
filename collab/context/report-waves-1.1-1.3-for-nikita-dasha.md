## 4. Работа над ошибками — где мы кружим

### v53b показал именно тот риск, который stocktake предсказал час назад

[Stocktake PR #12](https://github.com/NikitaMorgos/glava-bot/pull/12), раздел «Риски моей оценки», написан 2026-05-08 утром:
> «Любая новая Stage может открыть новый класс — Stage 3 LE при revision может удалять, Stage 4 LD при auto-patch может терять элементы»

v53b днём 2026-05-08:
> Stage 2: огурцы прошли через 6 защит. `chapters_restored=[]` обе итерации.
> Stage 3 Literary Editor: УДАЛИЛ эпизод тихо.
> Stage 4 PDF: 27 стр., «формально без ошибок».

**Защиты Stage 2 идеальные. Stage 3 — слепое пятно.** Ровно как предсказано.

### Что это значит про нашу работу

1. **Защиты которые мы построили — РАБОТАЮТ как обещано.** Не в этом критика. v53 показал что волна 1.3.3 закрыла GW out-of-scope; v51 показал что волны 1.2.3 + 1.3.x закрыли FC false positive deletion.

2. **Но мы строили защиты только там где появлялась мутация.** Stage 3 LE удаление было предсказуемо — Stage 3 это revision-агент, любой revision-агент может удалять. Защита `validate_revision_volume` — она для GW revision, не для LE. Этого пробела никто не видел до момента когда он проявился.

3. **Если бы я делал аудит структурных проблем с самого начала и держал его в репо** — Stage 3 LE был бы там как «слепое пятно: нет post-validator». Мы могли бы его закрыть в волне 1.2 или 1.3 проактивно, не реактивно.

### Это и есть «теряем за деревьями лес»

| Что сделали | Что упустили |
|---|---|
| Защита GW revision deletion (волны 1.2.2, 1.3.3) | Не закрыли Stage 3 LE deletion |
| Защита FC false positive (волны 1.2.3, 1.3.1, 1.3.2) | Не пересмотрели — может, проще запретить cross-chapter `legitimate_deletion` целиком (Кандидат A из stocktake, ~0.5 дня) |
| Ref-architecture для historical_notes (волна 1.1) | Не закрыли err_004 — дублирование текста справки в нарративе |
| 6 защитных функций на коде | Все одного типа (post-condition validators). Не пересматривали может ли constrained interface (hard contract) убрать классы целиком |
| 98 unit тестов | 0 интеграционных тестов на Stage 1→4 (интеграция тестируется только живыми прогонами Курсора) |
