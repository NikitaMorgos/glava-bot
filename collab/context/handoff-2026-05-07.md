**Стейт защиты на сейчас (после PR #7):**
- Evidence-check ВСЕГДА запускается при `legitimate_deletion=true`, независимо от volume ratio
- Verdict `blocked_phantom_evidence` ловит: quote отсутствует / topic-overlap < 25% / shared_count < 2
- FC v2.13 промпт обязывает FC перечислить 2-4 маркера эпизода и проверить ≥2 в evidence quote перед `legitimate_deletion=true`

**v51 ожидается от Курсора (на момент написания handoff).** Три сценария:

- **A.** FC v2.13 (промпт) НЕ ставит legitimate_deletion для огурцов вообще → огурцы остаются в книге → класс закрыт по существу

## Дисциплина протокола (что сохранять)

Разработано через серию инцидентов. Если новая сессия Опуса забудет — напомнить:

1. **Артефакт ≠ побочный эффект.** При любом «X сделано» — открыть сам артефакт, не верить proxy-метрикам типа «pytest passed», «exit 0», «PR merged». Зафиксировано в `collab/context/dev-review-protocol.md`.

2. **Posture-forcing observation.** При закрытии задачи — обязательно одно предложение конкретного наблюдения о финальном артефакте: «открыл PDF v46, на стр 5 видно...». Не «PASS, файлы на местах». Если закрывающий не может написать конкретно — задача не закрыта.

3. **Семантическая верификация ≠ формальная.** PASS-verdict с условиями (`ok_with_X`) требует cross-check на смысл условия, не только форму. Третий инцидент того же класса добавлен в protocol после v49.

4. **Defense in depth.** Промпт + код + тест. Промпт ловит большинство, код ловит остаток. Тест документирует ожидание.

5. **Не передавать override без обсуждения.** Override-флаги (`--allow-layout-mismatch`, `--allow-deletion-drop`, `--allow-fc-fail`) — только для аварийной отладки. При FAIL — пауза, отчёт, обсуждение, потом решение. Курсор после v45-инцидента это применяет, нужно не разрушить.

6. **Узкое ТЗ.** Если задача делегируется Курсору — явный список файлов «в scope» и «не трогать». Тогда детектор scope creep становится механическим («тронул ли файл вне списка?»).
