Два сценария выполнения задачи

Основной путь

~80% задач

Низкий / средний риск, только своя область, тесты зелёные

Тим-лид не участвует

Эскалация

~20% задач

Высокий риск, кросс-домен или тесты упали

Тим-лид получает уже готовый PR

Автоворота — что проверяется перед мёрджем

Проверка Как Блокирует мёрдж?
pytest tests/ -v Агент запускает локально перед коммитом Да — при любом FAIL
Файлы только в своём домене Правило в agent.mdc: список запрещённых путей, агент не может их записать Да — при нарушении
Самооценка риска в задаче Поле «Оценка риска» в task-файле: low/medium → авто, high → создать PR Да — при high
Защищённые файлы не изменены .env, _user_has_paid, pipeline_config.json — запрет на запись в правилах агента Да — всегда
Нет конфликтов с dev git merge --no-commit перед push Нет — агент решает или эскалирует

Классификация риска — кто мёрджит

Риск Примеры задач Кто мёрджит
low Текст промпта, SMM-контент, копирайт лендинга, стиль ответов бота Агент автономно
medium Новый агент в pipeline, новый блок лендинга, новый шаблон письма, новая команда бота Агент (тесты обязательны)
high Изменение форматов JSON-контрактов, DB-миграция, кросс-домен, payment-логика, новый сервис PR → тим-лид

Как это не ломается
Защита не в том, что тим-лид всё смотрит — защита в том, что агент физически не может записать в запрещённые файлы (правила агента) и не может смёрджить при упавших тестах (ворота). Тим-лид нужен только там, где автоматика не даёт ответа: архитектурные развилки и кросс-доменные задачи.
