## Контекст

GW промпт растёт через добавление, без рефакторинга:
- v2.14 (СТОП-ФРАЗЫ + bio_data) — ~1500 строк
- v2.15 (ANTI-DELETION при revision, волна 1.2.2) — ~1600
- v2.16 (REVISION SCOPE LOCK ЗАПРЕТ 0, волна 1.3.3) — 1692
- v2.17 (ЗАПРЕТ 8 пластиковость, Этап 1) — 1739
- v2.18 (ЗАПРЕТ 9 listing + ЗАПРЕТ 10 временные связки + Правило 2 усилено, task 036) — ~1900 ожидается

На каком-то этапе модель перестанет одновременно следовать 10+ запретам.

## Решение (когда сработает триггер)

Рефакторинг по структуре:

1. **`prompts/03_ghostwriter_v3.0.md`** — core промпт, 600-800 строк. Содержит:
   - Роль, контекст пайплайна
   - Top 5 ABSOLUTE rules (самые важные ЗАПРЕТЫ компактно)
   - Output schema
   - Phase A vs Phase B

2. **`prompts/gw_principles.md`** — отдельный файл, ~500 строк. Содержит:
   - Расширенные ЗАПРЕТЫ (0-10) с примерами
   - Стилистические правила (СТОП-ФРАЗЫ, characteristic words)
   - Historical examples (v43, v47-v53b, v54 регрессии)
   - Edge cases

3. **`prompts/gw_self_check.md`** — отдельный, ~200 строк. Содержит:
   - Чек-листы перед сохранением каждой главы (как в текущем ЗАПРЕТ 8)
   - Конкретные тесты («посчитай факты», «найди характерные слова»)

`pipeline_utils.load_prompt` модифицируется на `include:` синтаксис: core промпт включает principles + self_check через директиву. Подача в LLM — конкатенация всех 3 файлов, для модели это один промпт. Для нас — структурированная база.

## Альтернатива

**Не делать рефакторинг**, но:
- Контролировать длину автоматически (test в pre-commit: если v2.X.md > 2000 строк — warning)
- Перед каждой новой версией — review old rules: какие можно удалить (стали обобщёнными другими) или объединить
